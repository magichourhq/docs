Model Context Protocol (MCP) lets AI assistants call external tools. Magic Hour MCP lets compatible
assistants create and edit media through Magic Hour's API-backed tools. Connect the hosted server
once, then ask for an image or video result in plain English. The assistant selects tools,
starts jobs, waits for renders, and returns the finished files.

```text Hosted MCP endpoint
https://mcp.magichour.ai/
```

## What the server exposes

The current server builds tools from its bundled Magic Hour OpenAPI specification and adds helpers
for the media workflow:

- **Video:** talking photo, video editing and translation, animation, audio-to-video, subtitles, character replace,
  face swap, image-to-video, lip sync, text-to-video, and video-to-video
- **Image:** generation and editing, clothes and face editing, GIFs, headshots, upscaling, memes,
  QR codes, body/face/head swaps, background removal, and photo colorization
- **Audio inputs:** use audio files with talking-photo and other tools that accept audio. Voice
  generation and voice cloning are not currently exposed by the hosted MCP.
- **Workflow:** server health, file-upload URLs, face detection, project status and deletion, render
  waiting, and secure retrieval of completed image, audio, and video files

Magic Hour MCP reflects the API-backed tool catalog. It does not claim to expose every tool in the
Magic Hour web app.

## Before you connect

You need:

- A Magic Hour account for the Claude or ChatGPT OAuth connector sign-in flow
- For the Claude Code, Codex CLI, and Manus bearer-token setup below, a [Magic Hour API key](https://magichour.ai/developer?tab=api-keys&ref=docs-mcp-requirements&utm_source=docs&utm_medium=referral&utm_campaign=mcp)
- A client that supports remote Streamable HTTP MCP servers
- Enough Magic Hour credits for the generations you request

Tool discovery is public, but every tool call requires authentication. Real generation requests
spend Magic Hour credits, and creation tools return the credits charged with the project ID. Keep
your API key private and never commit it to source control.

<Tab title="Claude">

1. Open **Settings → Connectors** in Claude and add a custom connector.
2. Name it `Magic Hour` and use `https://mcp.magichour.ai/` as the connector URL.
3. If Claude asks for an OAuth client ID in Advanced settings, enter `magic-hour-mcp`.
4. Select **Connect**, sign in to Magic Hour if asked, and select **Allow** on the authorization page. A **Claude connector** API key is created automatically in your [Developer Hub](https://magichour.ai/developer?tab=api-keys&ref=docs-mcp-requirements&utm_source=docs&utm_medium=referral&utm_campaign=mcp); delete that key there to disconnect.
5. Enable the connector and ask Claude: `Call Magic Hour account_retrieve and confirm API access without generating media.`

A returned credit balance confirms API authorization. Keep account details private.

</Tab>

Start a new Claude Code session and ask it to call `account_retrieve` to confirm API access without

<Tab title="Hermes Agent">

Install [Hermes Agent](https://hermes-agent.nousresearch.com/docs/getting-started/installation/)
and configure its model provider separately. Connect Magic Hour as a custom MCP server; no
additional Magic Hour server or plugin is needed.

Set your Magic Hour API key in the shell that will launch Hermes:

```bash
export MAGIC_HOUR_API_KEY="YOUR_MAGIC_HOUR_API_KEY"
```

Merge this entry into `mcp_servers` in `~/.hermes/config.yaml` (or your selected profile’s config).
Keep the `${MAGIC_HOUR_API_KEY}` placeholder literal so the key stays out of the YAML:

```yaml
mcp_servers:
  magic_hour:
    url: https://mcp.magichour.ai/
    headers:
      Authorization: "Bearer ${MAGIC_HOUR_API_KEY}"
    timeout: 120
```

Check discovery, then start Hermes from the same shell:

```bash
hermes mcp test magic_hour
hermes chat
```

Ask Hermes: `Call mcp__magic_hour__account_retrieve to confirm API access without generating media.`
A returned credit balance confirms authorization; tool discovery alone does not.

Then try the [first request below](#try-a-first-request). Generation uses Magic Hour credits.
Keep the accepted project ID and resume its matching wait tool after an interruption rather
than submitting another paid job. Local attachments still need the [upload flow below](#using-input-files).

This custom connection does not imply inclusion in Hermes’ Nous-approved MCP catalog.
[Hermes MCP documentation](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp/)
explains configuration, tool filtering, and catalog review.

<Tab title="ChatGPT">

<Tab title="Manus">

1. Open **Settings → Connectors** in Manus, then select **Create → Custom MCP**.
2. Name the connector `Magic Hour`, choose HTTP, and enter `https://mcp.magichour.ai/`.
3. Add a header named `Authorization` with the value `Bearer YOUR_MAGIC_HOUR_API_KEY`.
4. After connecting, ask Manus: `Call Magic Hour account_retrieve and confirm API access without generating media.`

Manus receives and stores this API key with the connector. Use a dedicated key and revoke it in
your [Developer Hub](https://magichour.ai/developer?tab=api-keys) to remove its Magic Hour access.
Keep the key out of chat messages. Generation sends your prompt, settings, and explicitly selected
media to Magic Hour and spends Magic Hour credits; only send inputs authorized for that purpose.

## Verify API access before generating

Use `account_retrieve` to confirm API access, then check eligibility for the
intended generation. Tool discovery can work without credentials, and an invalid API key
can still receive `pong`; the account read checks actual API authorization.

`Authentication required` means the bearer token is missing. An account `401` means
authorization failed. Check the key and the environment that launched the agent before
reinstalling anything. Keep account details private.

## Add media generation workflows

The MCP gives your assistant access to Magic Hour tools. The [Magic Hour skills
cookbook](https://github.com/magichourhq/skills) adds workflows and published examples for
prompting, tool sequencing, output review, and recovery without duplicate paid jobs.

```bash
npx skills add magichourhq/skills --skill '*'
```

Choose your agent in the installer. You can also install one workflow from the
[cookbook](https://github.com/magichourhq/skills). Published examples record their
validation limits; tool availability alone does not establish output quality.

## Try a first request

Start with a prompt that does not require an uploaded file:

```text
Create a square cinematic image of a neon ramen shop at night. Wait for the Magic Hour job to
finish and show me the result.
```

Other examples:

| Goal                 | Example request                                                                 |
| -------------------- | ------------------------------------------------------------------------------- |
| Edit an image        | `Add realistic sunglasses to this portrait and preserve the person's identity.` |
| Animate a still      | `Turn this image into a five-second video with gentle camera movement.`         |
| Swap faces           | `Swap this source face onto the person in this target image.`                   |
| Make a talking photo | `Make this portrait speak using my audio file.`                                 |

## How render jobs work

Image and video creation is asynchronous. Audio status, waiting, and download helpers can also
retrieve existing API audio projects:

1. A creation tool starts the job and immediately returns a project `id` and `credits_charged`.
2. The assistant calls the matching `wait_for_image_project`, `wait_for_video_project`, or
   `wait_for_audio_project` helper.
3. The wait helper stops when the project is complete, has an error, is canceled, or times out.
4. Completed projects return `exact_download_urls`. Those signed URLs must be used exactly as
   returned without removing query parameters or appending expiration metadata.

Compatible clients can also receive completed media inline from the wait and download helpers.

## Using input files

The hosted server deliberately does not read a path on your computer. For local media, the complete
flow is:

1. Call `video_assets_generate_presigned_url`. Despite its name, it accepts image, audio, and video
   items.
2. Have the client or an upload bridge send the raw bytes to the returned `upload_url`.
3. Pass the matching returned `file_path` to the creation tool.

Direct public media URLs may work when they return stable raw file bytes, but uploaded Magic Hour
`file_path` values are more reliable. A browser attachment only works when the MCP client provides
the required upload bridge; the hosted server cannot fetch a caller-supplied local filesystem path.

## Recommended video guidance

Unless the user gives different instructions, guide the assistant to:

- Use Image-to-Video directly when the user already has an approved image to animate
- Use AI Image Editor first only when the requested appearance must change or the source needs editing
- Reuse reference images and preserve identity, style, color, lighting, and aspect ratio across scenes
- Omit optional `model` and `resolution` only when their defaults are compatible with the account
- For an image model recommendation, prefer `nano-banana-2-lite` only when account support is known;
  otherwise check account access and tool model metadata before choosing a model
- For an Image-to-Video model recommendation, prefer `ltx-2.5`
- Use Text-to-Video when visual consistency is not important

User instructions take precedence over these defaults.

For AI Image Editor, omitted `model` or `model="default"` currently selects `nano-banana`, which
requires a paid plan. On Free, explicitly request `model="flux-2-klein"`, `resolution="640px"`, and
`image_count=1`. Available credits alone do not unlock paid-only models or larger resolutions.
If a request returns `plan_upgrade_required`, choose a model and resolution supported by the account
or upgrade; do not retry the unchanged request. Do not silently change a user-selected model.

## Troubleshooting

- **Tools do not appear:** Restart the client after adding the server, then call `account_retrieve`.
- **Authentication fails:** For Claude or ChatGPT OAuth connections, reconnect, sign in to Magic Hour,
  and select **Allow**. For manual bearer-token clients, confirm the full API key is active and
  authentication uses `Authorization: Bearer YOUR_MAGIC_HOUR_API_KEY`. Then call `account_retrieve`
  to verify API access.
- **Codex cannot see the server:** Launch Codex from the shell where `MAGIC_HOUR_API_KEY` is set.
- **You only received a project ID:** Ask the assistant to call the matching `wait_for_*_project`
  helper and return the finished result.
- **A signed link fails:** Ask for the exact download URL again. Do not shorten it, strip its query
  parameters, or append `expires_at`.
- **A local attachment cannot be used:** Use a client with an upload bridge or upload the file first
  and provide its Magic Hour `file_path`.
